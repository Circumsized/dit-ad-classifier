# 多轮复审方法学（Review Methodology）

> 本 SOP 来自 2026-11-19 审计及其六轮复审的实战总结：每一轮都抓到上一轮
> 漏掉的问题，其中三轮的发现直接来自“声明与验证的落差”。适用场景：科研
> 代码库的修复批次、审计结论、或任何“声称已完成”的变更集。

## 1. 轮次设计

```
R0  全量审计        7 路视角并行（正确性/第二意见/静默失败/类型/安全/
                    简化/测试覆盖），互不知晓彼此结论
R1  fresh-eyes      审查员只拿 diff，不拿前轮发现清单（无锚定）
R2..Rn 交叉复审     可持前轮清单（标注锚定风险），任务为“找残留 +
                    找本轮修复引入的新缺陷”
终核 证伪轮         任务明确为“推翻终报的每一条声明”，逐条复现
```

**锚定披露**：持有前轮清单会系统性漏掉清单外的问题。每轮必须在报告中
声明审查员拿到了什么；R1 是唯一名实相符的 fresh-eyes 轮。

## 2. 每轮 SOP（八步）

1. **基线固化**：记录 commit sha、测试数、CI run 编号；后续所有数字引用
   这些锚点。
2. **复现探针**：用项目 venv 把“已修复”跑一遍，输出留档（探针写入仓库外
   临时目录，防仓库外模块劫持）。
3. **变异验证**：对每个修复注入等价缺陷（monkeypatch 或临时补丁），确认
   对应测试变红。**测试存在 ≠ 测试有效**——本次有两条修复的测试钉不住
   自己声称的行为（渲染 "None" 字面量全绿；还原 `_json_block` 消毒全绿）。
4. **靶向测试**：每批修复只跑受影响文件（2–40s），阶段末跑全量。
5. **删除亲验**：对每个“已删除”符号全仓 grep（含 tests/docs/configs），
   并确认无动态引用（`getattr`/`globals`/星号导入）。
6. **提交**：单主题、可独立回滚；message 写清缺陷证据、测试名、已知限制；
   用 `git commit -F`（`-m` 在部分 shell 下会吃掉反引号内容）。
7. **复审**：派新审查员对 diff 做证伪式审查（见 §1 轮次设计）。
8. **计数对齐**：文档数字必须来自 CI 实测并引用 run 编号——本地数字与
   CI 环境（no-torch 集合）系统性不同。

## 3. 三条铁律（本次审计用代价换来）

### 铁律一：删除声明必须 grep 亲验

**案例**：`experiment_payload_of_base` 被三个 commit message 先后声称删除，
审查员报告“已消失”，实际定义一直在（零引用 = F821/F841 结构上不可见，
py_compile 与 pytest 也都看不见）。

**防线**：删除契约测试——`tests/test_removed_symbols.py` 断言本仓库声称
删除的每个符号确实不存在；符号被重新引入时测试立即变红。新修复若删除
任何符号，必须同步追加断言。

### 铁律二：文档数字必须引用 CI run

**案例**：README 的 no-torch 计数在一天内经历 411（漏刷）→ 567（旧一代
CI）→ 573（实测）→ 576（新测试后实测），每次“刷新”都引用上一次的旧值。

**防线**：文档中的每个测试数字必须附 CI run 编号；run 结束当天核对，
新增测试当轮更新。本地收集数 ≠ CI 数（no-torch 环境集合不同）。

### 铁律三：新修复必须有变异测试证明

**案例**：null 渲染测试只断言 `"-" in row`——把实现改成渲染 "None" 字面
量，16 个测试全绿；`_json_block` 的消毒修复没有任何测试，还原后 43 个
测试全绿。

**防线**：每个“防回归”修复在提交前做一次注入式变异（内存中回退该修复），
确认目标测试变红；变异记录写进 commit message 或日志。

## 4. 审查员提示词要点（复用模板）

- 任务用**证伪框架**：“找出终报中过度声称、被弱化的让步、以及修了但修
  不完整的地方”，而非“请审查”。
- 给锚点：commit 范围、基线 sha、可复现的验证命令；不给结论。
- 要求每条发现附**可复现证据**（命令 + 输出摘要），禁止凭记忆断言。
- 要求结尾列「已尝试破坏但守住」清单——证明审查覆盖面，而非只列问题。
- 明确 READ-ONLY 约束与工具路径（venv python、探针目录）。

## 5. 工具链

| 工具 | 用途 | 说明 |
|---|---|---|
| `.venv/Scripts/python.exe -m pytest tests/ -q` | 全量门禁 | no-torch 契约由 CI 双矩阵验证 |
| `.venv/Scripts/python.exe -m ruff check dit/ tests/` | F821/F841/E9 | F821 抓未定义名（删除不完整的残留）；零引用定义仍需铁律一 |
| venv 探针（`-I`，临时目录） | 复现与对抗 | 防仓库外模块劫持 |
| `gh run view <id> --log` | CI 实测数 | 文档数字的唯一来源 |
| `git archive <sha>` | 时点复现 | 对拍历史行为（如渲染等价性） |

## 6. 反模式清单（本次全部出现过）

- 把“审查员说修了”当作“修了”（铁律一）。
- 用上一代 CI 的数字刷新文档（铁律二）。
- 测试只钉存在性不钉值（铁律三）。
- commit message 与树不一致（如漏记同批的代码变更）。
- 同一数字在文档多处不一致且只改其中一处。
- 复审轮次声称“独立”但实际持有前轮清单（锚定未披露）。
